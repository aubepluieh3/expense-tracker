# e2e

브라우저를 실제로 띄워 앱을 훑는 검증. Playwright 러너를 쓰지 않고 스크립트 3개로 두었다 —
검증이 67개뿐이고, 러너 설정 파일보다 스크립트 하나가 읽기 쉽다.

## 준비

```bash
npm install                              # playwright 포함
npx playwright install chromium          # 브라우저 바이너리 (한 번만)
cp .env.test.example .env.test.local     # 테스트 계정 채우기
```

`.env.local` 의 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` 를 그대로 쓴다.
계정 정보만 `.env.test.local` 에 따로 둔다 — anon 키는 프론트 번들에 들어가는 공개
값이지만 비밀번호는 진짜 비밀이다.

> **전용 계정을 쓸 것.** 매 라운드 시작에 그 계정의 거래를 전부 지우고 카테고리를
> 기본값으로 되돌린다. 본인이 쓰는 계정을 넣으면 데이터가 사라진다.

## 실행

개발 서버가 `5173` 에 떠 있어야 한다 (`npm run dev`).

```bash
npm run test:e2e            # 통합 검증 3회 (기본)
npm run test:e2e -- 1       # 1회만
npm run test:ux             # 사용성 — 탭 수와 마찰 측정
npm run test:reset          # 계정만 초기화
```

## 파일

| | |
|---|---|
| `config.mjs` | 설정을 파일에서 읽는다. 코드에 계정을 박지 않기 위한 유일한 진입점 |
| `reset.mjs` | 계정을 신규 가입 직후 상태로. anon 키로만 동작하므로 초기화 자체가 RLS 확인이다 |
| `run.mjs` | 통합 검증. 인증 · 빈 상태 · 등록 · 수정 · 삭제 · 월 이동 · 위젯 · 필터 · 통계 · 카테고리 · 설정 · 데스크톱 · 콘솔 에러 |
| `usability.mjs` | 통과/실패가 아니라 **마찰**을 찾는다. 한 주치를 기록하며 동작마다 탭 수와 시간을 센다 |

## 실패하면 화면을 본다

`run.mjs` 는 실패한 순간의 스크린샷을 `e2e/shots/` 에 남기고, 에러 줄에 그때의
**열린 다이얼로그 수와 URL** 을 붙인다.

```
R2 [카테고리] 급여 카테고리 지정 이동
   locator.check: Timeout 30000ms  [dialog=0 url=/settings/categories] → e2e/shots/fail-R2-01.png
```

추측하지 않고 보고 판단하기 위한 장치다. 실제로 이 방식으로 앱 버그 6건과 테스트
결함 4건을 구분해 냈다. 그중 두 가지는 기억해 둘 만하다.

- **날짜 경계.** `오늘 + 3일` 로 "이 달 안의 미래 날짜" 를 만들었는데 7월 29일에는
  8월 1일이 됐다. 다음 달로 넘어간 거래는 이 달 목록에 안 나오므로 검증이 성립하지
  않는다. 지금은 말일로 당긴다.
- **시트 오버레이.** `Sheet` 는 화면 전체를 덮는 `닫기` 버튼을 깐다. 시트를 닫고
  `detached` 를 기다리지 않으면 다음 클릭이 그 오버레이로 간다. 3회 중 1회만 깨져서
  앱 버그로 보였다. 시트를 닫는 모든 검증은 detach 를 기다린다.

## 왜 3회인가

한 번만 돌리면 위와 같은 경합을 못 잡는다. 3회는 산발적 실패를 드러내면서
(같은 실패가 1/3 이면 경합, 3/3 이면 결정적) 한 번에 끝나는 타협점이다.
